# Marco 3: IA de qualquer provedor — Plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para implementar este plano tarefa por tarefa. Os passos usam checkbox (`- [ ]`).

**Objetivo:** trocar o cliente do Gemini por um cliente único compatível com OpenAI, com presets de provedores, chave no cofre do sistema e uma aba IA com botão Testar.

**Arquitetura:**
- `openrok/ia.py` passa a ter os presets e um `ClienteIA` (`httpx`, `POST {base}/chat/completions`). A interface usada pelo vigia continua `escolher(pergunta, opcoes) -> letra | None`, então o vigia não muda.
- Toda falha vira `FalhaIA` com mensagem já traduzida. O vigia já converte qualquer exceção em evento `ErroIA`, então nenhuma exceção chega à UI.
- A chave fica no cofre do sistema (`keyring`), em `openrok/cofre.py`. A config (JSON) guarda só o provedor, o modelo e a URL do personalizado.
- `ia_de_config(config, idioma, cofre)` monta o cliente a partir da config. O app usa essa função como `ia_fabrica` e remonta o cliente quando a aba IA muda algo.

**Stack:** Python 3.12, `httpx` 0.28, `keyring` 25, PySide6, pytest-qt, `httpx.MockTransport`.

**Spec:** `docs/superpowers/specs/2026-10-19-openrok-2-design.md` (§1 critério da IA, §9, §10 aba IA, §14 testes de `ia`, §15 marco 3)

## Restrições globais

- Mesmo estilo do pacote: identificadores em português, comentários em inglês com cabeçalhos `# ===`.
- **Requisição:** `POST {base}/chat/completions`, timeout de **6 s**, **nenhuma nova tentativa**. O prompt é o `IDIOMAS[idioma]["prompt"]` atual, só com as opções não vazias.
- A sugestão só é desenhada se `extrair_letra` devolver uma letra cuja opção não está vazia. **A IA nunca grava no banco.**
- **Erros traduzidos** (`textos`, `en` e `pt` com as mesmas chaves):
  - `401` ou `403` → "chave inválida";
  - `400` com "api key" no corpo (o Gemini antigo devolvia assim) → "chave inválida";
  - `429` → "limite do plano gratuito atingido";
  - timeout → "IA demorou demais";
  - falha de conexão → "não conectou em {base}";
  - `404` → "modelo não encontrado: {modelo}";
  - qualquer outro status → "erro {status} do provedor";
  - JSON sem `choices[0].message.content` → "resposta inválida".
- **Presets**, nesta ordem (gratuitos primeiro). Modelos e URLs conferidos na documentação dos provedores em 2026-10-21:

| id | Nome | Base URL | Modelo padrão | Chave | Grátis | Onde pegar a chave | Corpo extra |
|---|---|---|---|---|---|---|---|
| `gemini` | Google Gemini | `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-3.5-flash-lite` | sim | sim | `https://aistudio.google.com/apikey` | `temperature: 0` |
| `groq` | Groq | `https://api.groq.com/openai/v1` | `openai/gpt-oss-20b` | sim | sim | `https://console.groq.com/keys` | `temperature: 0` |
| `openrouter` | OpenRouter | `https://openrouter.ai/api/v1` | `openrouter/free` | sim | sim | `https://openrouter.ai/keys` | `temperature: 0` |
| `ollama` | Ollama | `http://localhost:11434/v1` | `llama3.2` | não | sim | — | `temperature: 0` |
| `lmstudio` | LM Studio | `http://localhost:1234/v1` | `""` (o carregado) | não | sim | — | `temperature: 0` |
| `openai` | OpenAI | `https://api.openai.com/v1` | `gpt-6-luna` | sim | não | `https://platform.openai.com/api-keys` | `temperature: 0`, `reasoning_effort: "none"` |
| `anthropic` | Anthropic | `https://api.anthropic.com/v1` | `claude-haiku-5-5` | sim | não | `https://platform.claude.com/settings/keys` | nenhum (a API recusa `temperature` < 1) |

- **Modelo vazio** (LM Studio, ou o usuário apagou o campo): o cliente faz `GET {base}/models` uma vez e usa o primeiro `id`.
- **Compatibilidade:** sem chave no cofre, o preset `gemini` usa `GEMINI_API_KEY` ou `GOOGLE_API_KEY` do ambiente, como antes.
- **Dependências:** entram `httpx` e `keyring` no `requirements.txt`; sai `google-genai`.

## Foco da revisão

1. **Provedor que exige chave, sem chave:** a IA fica desligada sem erro (`ia_de_config` devolve `None`), e o Testar mostra "informe a chave". Teste na tarefa 2 e na 3.
2. **Ollama ou LM Studio fechados:** falha de conexão rápida com "não conectou em {base}", sem esperar os 6 s e sem travar a UI. Teste na tarefa 1 (`ConnectError`) e na 3 (Testar roda fora da thread da UI).
3. **Resposta estranha do modelo** (`content` nulo, sem `choices`, texto que não é letra): `escolher` devolve `None` ou levanta `FalhaIA`, nunca outra exceção. Teste na tarefa 1.
4. **Cofre indisponível** (Linux sem Secret Service): a chave vale só na memória até fechar o app, e a aba IA avisa isso. Teste na tarefa 2.
5. **Trocar provedor ou chave com o vigia rodando:** o vigia passa a usar o cliente novo na próxima pergunta, sem reiniciar. Uma resposta atrasada do cliente antigo para uma pergunta velha continua descartada (`numero`). Teste na tarefa 4.

- Produz:
  ```python
  class Cofre:                                   # keyring, serviço "OpenRok", usuário = id do provedor
      disponivel: bool                           # False depois de qualquer erro do keyring
      def ler(self, provedor: str) -> str | None
      def gravar(self, provedor: str, chave: str) -> None   # "" apaga
  class CofreMemoria:                            # mesma interface, só um dict (testes e padrão da janela)

  # Config ganha:
  ia_provedor: str = "gemini"
  ia_modelo: str = ""        # "" = modelo padrão do preset
  ia_base_url: str = ""      # só para "personalizado"

  def ia_de_config(config: Config, idioma: str, cofre) -> ClienteIA | None
  ```
- **Regras de `ia_de_config`:**
  - preset = `preset(config.ia_provedor)`;
  - base = `config.ia_base_url` no `personalizado`, senão `preset.base_url`; `personalizado` com base vazia → `None`;

  - chave = `cofre.ler(preset.id)`; no `gemini` sem chave, `GEMINI_API_KEY` ou `GOOGLE_API_KEY`;
  - `preset.exige_chave` sem chave → `None`.
- **Regras do `Cofre`:** qualquer exceção do `keyring` (inclusive `NoKeyringError`) marca `disponivel = False` e passa a usar um dict interno. Nenhuma exceção sai do `Cofre`.
